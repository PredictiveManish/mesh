01 — The memory wall

Pooled VRAM is fiction.

A model has to fit on one node before it can be trained on any of them. So the ceiling is set by your largest single GPU, not by the sum of your fleet. Add a thousand more 4 GB laptops and you still cannot hold a 7B model.

02 — Three commands

Ask the fleet, don't guess at it.

No cluster, no scheduler, no config file. Point mesh at the machines you already have.

01

scan

Probes a machine or a whole fleet and reports what actually fits.

mesh scan --fleet 100
02

plan

Placement, sync interval, throughput and ETA for one specific job.

mesh plan --params 7.2 --mode lora
03

up

Coordinator and live dashboard in one command. Add real nodes with mesh agent.

mesh up --demo
03 — The dashboard

Every machine, as the fleet sees it.

Online now, active 24 h, pooled VRAM, a capacity ladder that shows exactly where your fleet falls off, installs per day, the VRAM tier mix, GPU inventory and city-level geography — opt-in, coarse, and never an IP address.

04 — What it answers

Questions that cost a week to answer badly.

QuestionWith meshTypical answer today
Largest model this fleet can hold computed per node from the census a guess, then a failed run
How many machines can run a 7B? counted exactly "we have 646 GB pooled"
How often should nodes synchronise? auto-tuned so upload ≤ 20% of compute a constant copied from a paper
How long until the run finishes? ETA from measured throughput unknown until it ends

Built for

  • Labs and universities with a mixed bag of GPUs and no cluster team
  • Enterprises with idle workstations and a data-residency rule that rules out offshore cloud
  • Anyone deciding whether to rent an A100 or use what they already own

Not built for

  • Frontier training. A hundred mixed laptops are worth roughly one H100 of effective throughput — mesh will tell you that number too
  • Models larger than one node. Pipeline parallelism is not built yet
  • Untrusted strangers. Verification is a gate, not a proof
